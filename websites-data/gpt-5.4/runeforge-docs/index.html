Getting started

Predictable state, one rune at a time.

Runeforge is a 4 kB state-management library for JavaScript apps. It gives you a single API — forge() — that works the same in vanilla JS, React, Solid, Svelte, and Vue. There are no providers, no boilerplate, no proxies. Just stores, actions, and subscriptions.

Brand new? The 5-minute quickstart walks you through building a counter, a todo list, and an async fetcher. You'll write less code than any state library you've used before.

Install

Runeforge is published to npm under the same name. The core package has zero dependencies. Each framework adapter is its own ~1 kB package.

# Core + React adapter (most common)
npm install runeforge @runeforge/react

Hello, store.

Every Runeforge app starts with a forge() call. You pass it the initial state and a map of actions. You get back a store with get(), set(), subscribe(), and your action methods.


    


    
Three things to remember

    
Runeforge keeps the surface area tiny. Once you understand these three concepts, the rest is composition:


    

      

        
01

        
Stores hold state

        
A store is the unit of state. Read with get(), write with set(), observe with subscribe(). Stores compose; you can derive one store from another.

        Read about stores →
      

      

        
02

        
Actions describe changes

        
Actions are plain functions on a store. They get the current state and return the next state. There is no reducer, no dispatch, no string types.

        Read about actions →
      

      

        
03

        
Selectors keep components tiny

        
Selectors derive computed values without re-renders. Components subscribe to a selector, not to the whole store, so they only update when the slice they care about changes.

        Read about selectors →
      

    


    
Why another state library?

    
Runeforge sits between two extremes. Redux makes every state change explicit and traceable but takes a lot of boilerplate. Signal-based libraries are very ergonomic but rely on framework-specific reactivity. Runeforge is framework-agnostic and explicit, but with a much smaller surface than Redux.
