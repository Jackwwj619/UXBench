Core concept

Actions & selectors.

Actions describe how state changes. Selectors describe how state is read. Together they give you a one-way data flow without the ceremony of Redux.

Actions

An action is a function on a store. It receives the current state and any arguments you pass, and returns the next state — or a partial of it.

const cart = forge({
  state: { items: [] as Item[], coupon: null as string | null },
  actions: {
    add:    (s, item: Item)         => ({ items: [...s.items, item] }),
    remove: (s, id: number)         => ({ items: s.items.filter(i => i.id !== id) }),
    apply:  (s, code: string)       => ({ coupon: code }),
    clear:  ()                       => ({ items: [], coupon: null }),
  },
});

// call them like methods
cart.add({ id: 1, name: "Espresso", price: 3.50 });
cart.apply("BLOOM10");

Rules of thumb

  • Return, don't mutate. Always return a new object. Spread, map, filter — but never assign in place.
  • Return a partial. The partial is shallow-merged with current state, so you only return what changed.
  • Stay synchronous if possible. Keep async work in effects (see the Async & effects guide). It makes actions trivially testable.
  • Name actions for what they do, not how they do it. checkout() is better than setCheckoutState(true).

Selectors

A selector is a pure function from state to a derived value. Components — and any subscriber, really — use selectors so they only re-render when the value they care about changes.

const totalPrice = (s: ReturnType<typeof cart.get>) =>
  s.items.reduce((sum, i) => sum + i.price, 0);

cart.subscribe((s) => render(totalPrice(s))); // fires every change
cart.select(totalPrice).subscribe(render);          // fires only when total actually changes

Composing selectors

Selectors compose like any other pure functions. For more involved derivations across multiple stores, prefer derive() — it caches and only recomputes when its inputs change.

import { derive } from "runeforge";
import { cart, coupons } from "./stores";

export const grandTotal = derive([cart, coupons], (c, cs) => {
  const sub = c.items.reduce((s, i) => s + i.price, 0);
  const off = c.coupon ? cs.discountFor(c.coupon) : 0;
  return { sub, discount: off, total: Math.max(0, sub - off) };
});

Reusable action creators

For common patterns, Runeforge ships builder helpers like asyncSlice(), listSlice(), and formSlice(). They generate action sets so you don't write the same CRUD by hand.

import { forge, listSlice } from "runeforge";

type Todo = { id: number; text: string; done: boolean };

export const todos = forge({
  state:   listSlice<Todo>().state,
  actions: listSlice<Todo>().actions("id"),
});

// generated: add, remove, replace, update, clear, byId, has, count
todos.add({ id: 1, text: "Write docs", done: false });
todos.update(1, (t) => ({ done: true }));

Action middleware

Middleware wraps actions. Use it for logging, time-travel, persistence, and analytics. Middleware are pure functions that run before and after every commit.

import { use } from "runeforge";

use((next) => (action, args) => {
  const t0 = performance.now();
  const r  = next(action, args);
  console.log(`${action.store}.${action.name}`, `${(performance.now() - t0).toFixed(1)}ms`);
  return r;
});

The order is the order you call use() in. Devtools, persistence, and time-travel are all middleware — and you can write your own with the same signature.
